## 1. Архитектура (кратко)

- PowerShell 5.1 + WPF, без сборки. Ядро `src/Core/IPADredd.Core.psm1` (16 файлов, без UI), GUI `src/GUI` (XAML + обработчики `Pages/*.ps1`), фоновые задачи — runspace-пул и очередь сообщений (`src/GUI/TaskRunner.ps1`).
- Внешние инструменты: `ipatool-cpp` (App Store), `idevice_id`/`ideviceinfo`/`ideviceinstaller` (USB).
- Данные: `Files/` (настройки, списки, истории), `Apps/` (IPA), `Logs/`, `~/.ipatool/` (сессии, совместимо с консольной 4.2).

Архитектура здравая: ядро отделено от UI, есть отмена/таймауты процессов, маскирование журналов, атомарная (почти) запись файлов, собственный тест-раннер и самопроверка GUI. Переписывать стек **не нужно**: WPF даёт всё, что требуется для качественного интерфейса (виртуализация, шаблоны, темы). Ограничение стека — только Windows (macOS/Linux обслуживает консоль upstream).

## 3. Сломано / требует исправления (P0)

1. **Прогресс загрузки** (`Get-DreddProgressFromLine`): не понимает `PROGRESS:N` → пользователь не видит процентов. Подтверждено журналом 24.10.
2. **Засорение журнала**: каждая строка прогресса пишется как DEBUG в файл (`Add-DreddLog` пишет Debug в файл всегда). 11 тыс. строк за 2 загрузки.
3. **DSID в журнале**: `kbsync --refresh` выводит `dsid=…`, маскирование его не покрывает (`Logging.ps1: ReSecretKv`). Это идентификатор аккаунта — личные данные. `kbsync` должен вызываться с `-QuietOutput`, а `dsid` маскироваться.
4. **Запись файлов не атомарна** (`Platform.ps1: Write-DreddTextFile`: Copy + Delete). При сбое между ними возможен полузаписанный файл. Нужен `File.Replace`.
5. **Дубли в истории покупок**: одно и то же приложение может прийти несколько раз — нужна дедупликация по ID.
6. **Устаревший ipatool-cpp** в `MainApp` (12.10.2026). Upstream 4.3.2/4.3.3 исправил SSL через прокси и вход при включённом CFG. Обновление бинарника — ручное действие (скачать релиз upstream), автоматически не делаю.

## 4. Библиотека покупок Apple ID — что возможно на самом деле

**Что даёт ipatool-cpp** (`list-purchases --all`, проверено на реальном аккаунте): `id`, `kind` (`iOS App`, `Subscription`, `In-App Purchase`, …), `name`, `price`, `purchaseDate`. Это **история покупок Apple ID** (то же, что «История покупок» в настройках аккаунта): каждое приложение, которое аккаунт когда-либо «покупал» или «получал» бесплатно, по годам начиная с 2008. Нет: bundle id, иконки, текущей версии, размера, признака «доступно для загрузки».

**Дополняем публичным iTunes Lookup API** (`itunes.apple.com/lookup?id=…&country=XX`, без авторизации, пачками по 150): иконка, текущая версия, bundle id, min iOS, размер, разработчик. Если ID не найден в регионе аккаунта — приложение снято с продажи или недоступно в регионе.

**Что нельзя определить честно и как это показываем:**
- «Можно ли скачать» знает только сервер Apple в момент загрузки. Поэтому статус «Можно скачать» означает «есть в App Store региона аккаунта и куплено» — на практике загрузка проходит. Для приложений, которых нет в магазине, статус «Нет в App Store» с пояснением: «Apple часто отдаёт купленные ранее приложения после снятия с продажи, но не всегда — можно попробовать».
- «Недоступно для загрузки» показываем **только после реальной неудачной попытки** с текстом ошибки Apple, а не по догадке.
- «Не удалось проверить» — если Lookup не ответил (сеть) или регион аккаунта неизвестен.
- Статуса «Не приобретено» в библиотеке покупок нет вообще: все записи взяты из истории покупок. В поиске показываем «Нет в истории покупок» только после успешного полного сканирования и с оговоркой (Семейный доступ и покупки других аккаунтов туда не входят).
- **Устанавливалось ли приложение на устройство — по истории покупок узнать нельзя.** Повторные загрузки Apple в историю не пишет. Мы знаем только: «скачано IPA Dredd / лежит в локальной библиотеке». Список установленного на подключённом iPhone можно получить отдельно (`ideviceinstaller list`) — это P3.

## 6. GUI: проблемы и концепция

Проблемы текущего интерфейса (по снимкам):
- Журнал занимает ~170 px на **каждом** экране — основная таблица зажата.
- Карточка в карточке, скругления 10 px, «пилюли» сегментов, крупный H1 24 px + подзаголовок — много декоративного, мало рабочего места.
- Главная — 4 полупустые карточки и ряд «быстрых действий», дублирующих навигацию.
- Каталог: 5 источников, кнопки переносятся во вторую строку, колонка «Статус» почти всегда пустая.
- Счётчик фоновых задач показан дважды (боковая панель и строка состояния).
- В EN-интерфейсе единицы «МБ».

Концепция («сдержанный Windows-инструмент», как Fluent-приложения уровня Windows Terminal / Visual Studio Installer):
- Нейтральная палитра (графит вместо сине-фиолетового), один акцентный цвет, статусы — цветом текста, а не плашками.
- Единая сетка: отступы 4/8/12/16/24, радиусы 4 (кнопки, поля) и 6 (контейнеры), высота контролов 30, строка таблицы 36 (покупки — 44 с иконкой 32).
- Заголовок страницы 20 px, подзаголовок — одна строка; панель действий страницы — одна строка над таблицей.
- Журнал свёрнут в строку состояния (последнее сообщение + число задач); разворачивается по клику или Ctrl+L, состояние запоминается.
- Навигация: компактная, выделение активного пункта тонкой полосой акцента слева.
- Клавиатура: Ctrl+F — поиск на текущем экране, Enter — скачать выбранное, Ctrl+A — выбрать всё, F5 — обновить/сканировать, Delete — удалить файл (с подтверждением).
- Состояния пустых списков, загрузки и ошибок — в центре таблицы, с одним понятным действием.

## 8. Безопасность и надёжность

- Пароль: не хранится, живёт в памяти одного вызова; передаётся аргументом `-p` (видно в списке процессов несколько секунд) — альтернатива «Войти через консоль» есть. ✔
- Сессии: `~/.ipatool`, 4.3 только перемещает файлы, не читает. ✔
- Журналы: email и пароли маскируются ✔; **DSID — нет** ✖ (исправляется).
- Кэш покупок: названия приложений по аккаунту — личные данные. Хранить в `Files/Purchases/<хеш email>.json` (без email в имени файла), исключить из git и релиза.
- Выход: `auth revoke` + удаление активных файлов. ✔
- Сбой загрузки: временная папка удаляется в `finally` ✔; очередь в памяти теряется при закрытии (P2).
- Обход авторизации Apple, DRM или лимитов не делается и не планируется.

## 9. Риски

- Зависимость от неофициального `ipatool-cpp`: Apple может изменить протокол; `list-purchases` помечен как experimental.
- Регион: Lookup по региону аккаунта; если `auth info` вернёт не двухбуквенный код — статусы будут «Не удалось проверить».
- Apple может временно блокировать аккаунт за частые запросы — сканирование только по кнопке, Lookup пачками.
- Большие библиотеки (1000+): нужна виртуализация списка и фоновая загрузка иконок (сделано).
- PowerShell 5.1: компиляция C#-помощников при старте (~1–2 с).
