# Журнал архитектурных решений (ADR)

Формат записи: контекст → решение → последствия. Статусы: *принято*, *заменено ADR-N*, *отклонено*. Новое решение добавляется в конец, старые не переписываются: при смене решения заводится новый ADR со ссылкой на прежний.

---

## ADR-001. 4.3 — отдельная изолированная папка
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** В репозитории есть рабочие 4.1.2 (корень) и 4.2.0 (`IPA_Downloader_4.2.0/`). Пользователи могут продолжать ими пользоваться, а их поведение служит эталоном.

**Решение.** Новая версия живёт в `IPA_Dredd_4.3.0/`. Исходники 4.1, 4.2 и GUI-прототипа не меняются.

**Последствия.** Возможна временная дублирующая логика (консоль 4.2 и ядро 4.3). Общие данные (`~/.ipatool`) должны оставаться совместимыми (ADR-005).

## ADR-002. Стек GUI 4.3: Windows PowerShell 5.1 + WPF, ядро отдельно от UI
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** Рассматривались варианты:

| Вариант | За | Против |
|---|---|---|
| **PowerShell 5.1 + WPF** | Есть в каждой Windows 10/11, без сборки и установки; вся существующая логика на PowerShell; прототип уже на WPF; разработку можно проверить на этой машине | Только Windows; многопоточность в PowerShell требует аккуратности |
| .NET 8 + Avalonia | Настоящий кроссплатформенный GUI, строгая типизация, удобные тесты | На машине разработки только .NET Runtime 8, **SDK нет**: собрать и проверить нельзя без установки; переписывание всей логики на C#; пользователю нужен .NET Runtime или self-contained сборка по ~70 МБ на платформу |
| Python + Tkinter/Qt | Кроссплатформенно | Новый язык в проекте, на целевых машинах Python не гарантирован, Tkinter выглядит устаревше |

Пользователь работает на Windows; macOS/Linux обслуживает консоль 4.2.

**Решение.**
1. GUI 4.3 — Windows PowerShell 5.1 + WPF (XAML в отдельных файлах).
2. Бизнес-логика вынесена в модуль `IPADredd.Core` без `Read-Host`/`Write-Host` и без WPF. Модуль совместим с Windows PowerShell 5.1 и PowerShell 7 (кроссплатформенные пути и вызовы).
3. GUI под macOS/Linux — отдельный этап ROADMAP. Варианты: новый фронтенд поверх ядра (Avalonia, хостящий PowerShell, или консольный фронтенд на ядре 4.3) либо перенос ядра на C#. Решение принимается после стабилизации 4.3.

**Последствия.** Запуск двойным кликом по `.bat`, без сборки. На macOS/Linux GUI 4.3 нет, там остаётся консоль 4.2. Ядро можно покрывать тестами без GUI.

## ADR-003. Фоновые операции: runspace + очередь сообщений, процессы без колбэков
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** GUI не должен зависать при входе, загрузке, чтении истории покупок, сканировании устройств и установке. Обработчики `Process.OutputDataReceived` в PowerShell выполняются в потоке без runspace и роняют процесс.

**Решение.**
- Каждая длительная операция выполняется в отдельном runspace из пула. В нём импортируется `IPADredd.Core`.
- Связь с UI идёт через потокобезопасную очередь (`ConcurrentQueue`) с сообщениями `log` / `progress` / `status`. UI разбирает её по `DispatcherTimer` (≈100 мс). Результат забирается через `EndInvoke` в потоке UI.
- Внешние процессы запускаются через `System.Diagnostics.Process`, stdout/stderr читаются циклом опроса `ReadLineAsync()`. Отмена через `CancellationToken` убивает процесс (на Windows `taskkill /T /F`), есть таймауты.

**Последствия.** Отмена работает для всего, что запускает внешний процесс: загрузки, версий, установки, истории покупок. Операции не блокируют окно. Код UI не трогает объекты из чужих потоков.

## ADR-004. Поиск бинарников вместо копирования MainApp
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** `MainApp` весит ≈200 МБ для всех платформ, а актуальные бинарники лежат в `IPA_Downloader_4.2.0/MainApp`.

**Решение.** 4.3 ищет папку бинарников по порядку:
1. путь из настроек (`BinaryRoot`);
2. `IPA_Dredd_4.3.0/MainApp`;
3. `../IPA_Downloader_4.2.0/MainApp`;
4. `../MainApp` (4.1).

Внутри выбирается подпапка по ОС и архитектуре, как в 4.2. На macOS/Linux `ideviceinstaller`/`idevice_id`/`ideviceinfo` берутся из `PATH`. Скрипт `tools/Build-Release.ps1` собирает самодостаточный zip с копией `MainApp`.

**Последствия.** В рабочем дереве нет дублей бинарников. В диагностике видно, какая папка выбрана и почему.

## ADR-005. Совместимость с `~/.ipatool` консольной 4.2
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** 4.2 считает вход выполненным по маркеру `~/.ipatool/login`, хранит неактивные аккаунты в `~/.ipatool/<email>/` и при `KeychainEnabled=False` **удаляет** `keychain-passphrase` (риск A7).

**Решение.**
- 4.3 использует ту же раскладку: активные `account`/`cookies`/`login` и папки `<email>/`.
- После успешного входа 4.3 сама создаёт маркер `login` (исправление G2).
- Шифрование сессии keychain passphrase **выключено по умолчанию**, как в 4.2. Если включить его в настройках (только Windows), passphrase сначала сохраняется через DPAPI и только потом используется (исправление G3). Пользователь получает предупреждение, что консоль 4.2 с `KeychainEnabled=False` удалит этот файл.
- Если `keychain-passphrase` уже существует, 4.3 его использует, даже если настройка выключена, и ничего не удаляет.

**Последствия.** 4.2 и 4.3 можно запускать по очереди. 4.3 никогда не удаляет чужие файлы passphrase.

## ADR-006. Вход в Apple ID из GUI
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** Проверено: без терминала `ipatool auth login` stdin не читает и требует `-e EMAIL -p PASSWORD` (2FA через `-a CODE`). Пароль в аргументах виден в списке процессов, пока идёт вызов (несколько секунд).

**Решение.**
- Основной способ — форма в GUI (email, пароль в `PasswordBox`, код 2FA). Пароль живёт только в памяти, передаётся одному вызову ipatool и затирается из журнала (маска `***`). 4.3 его нигде не сохраняет.
- Если ответ похож на запрос 2FA, показывается поле кода, затем повторный вызов с `-a`.
- Альтернатива — «Войти через консоль»: интерактивный `auth login` в отдельном окне, пароль вводится скрыто и в аргументы не попадает. После закрытия окна GUI проверяет `auth info` и создаёт маркер.
- Риск передачи пароля аргументом описан в [SECURITY.md](SECURITY.md).

**Последствия.** Вход без консоли возможен. Для общих компьютеров рекомендуется консольный вход. Распознавание текста запроса 2FA **не проверено** на реальном аккаунте.

## ADR-007. Имена файлов IPA без email и без перезаписи
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** 4.2 пишет email в имя файла (A2) и перезаписывает совпадения (A3). Прототип добавляет метку времени (G7).

**Решение.** Шаблон по умолчанию: `{Name}_{Version}_iOS_{MinIOS}+.ipa`. При совпадении имени добавляется суффикс `_2`, `_3`… Добавление аккаунта в имя — настройка `FileNameIncludeAccount` (выключена). Аккаунт и App Store ID записываются в историю `Files/DownloadHistory.json`.

**Последствия.** Имена файлов отличаются от 4.2. Библиотека 4.3 читает IPA с любыми именами, поэтому для просмотра это не важно.

## ADR-008. Загрузка во временную папку через `-o`
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** 4.2 скачивает в корень скрипта, при старте удаляет оттуда все `*.ipa` и потом переносит все `*.ipa` (A4).

**Решение.** Каждая загрузка идёт в свою временную папку (`%TEMP%/IPADredd/<guid>/`) через `download -o`. После успеха файл проверяется (zip читается, есть `Info.plist`) и переносится в папку загрузок. Временная папка удаляется, в том числе при отмене.

**Последствия.** Файлы пользователя вне временной папки не трогаются. Прогресс можно оценивать по росту размера файла во временной папке.

## ADR-009. Лицензия (`--purchase`) — явный выбор
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** 4.2 всегда добавляет `--purchase` (A5) и записывает покупку без проверки результата (A6).

**Решение.** В окне загрузки есть флажок «Получить бесплатную лицензию, если приложения нет в покупках». По умолчанию он включён, как в 4.2, и сохраняется в настройках. «Только получить лицензию» — отдельное действие с подтверждением. В `PurchasedAppsList.json` пишется только при коде возврата 0.

**Последствия.** Поведение 4.2 сохранено, но стало видимым и управляемым.

## ADR-010. Разбор plist через C#-помощник
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** Регулярки не читают бинарные plist (A1, подтверждено на реальном IPA).

**Решение.** Небольшой класс на C# (`Add-Type`, компилируется при запуске) разбирает XML- и бинарные (`bplist00`) plist в словари. Из IPA читаются `Info.plist` (имя, bundle id, версия, сборка, MinimumOSVersion) и `iTunesMetadata.plist` (App Store ID, исполнитель). Apple ID покупателя из `iTunesMetadata.plist` **не** читается и не показывается.

**Последствия.** Первая загрузка модуля ≈1 с на компиляцию. Метаданные корректны для любых IPA.

## ADR-011. Локализация и темы
**Дата:** 2026-10-17 · **Статус:** принято

**Решение.** Строки лежат в `src/Localization/ru.json` и `en.json` (ключ → текст), элементы XAML помечаются `x:Uid`. Цвета задаются через `DynamicResource`; палитры тёмной (по умолчанию) и светлой темы находятся в `src/GUI/Themes/*.xaml` и меняются без перезапуска. Язык тоже переключается на лету.

**Последствия.** Новый текст = ключ в двух JSON. Тест проверяет, что наборы ключей RU и EN совпадают.

## ADR-012. Журнал в файл с маскированием
**Дата:** 2026-10-17 · **Статус:** принято

**Решение.** Все операции пишутся в журнал окна и в `Logs/yyyy-MM-dd.log`. Перед записью сообщения проходят через `Protect-LogText`: email → `m***@domain`, значения `-p`, `--password`, `--keychain-passphrase`, `-a`/`--auth-code` → `***`. Режим отладки добавляет `--debug` к ipatool. Его вывод тоже маскируется, но может содержать заголовки и cookies, поэтому в интерфейсе есть предупреждение.

## ADR-013. Обновление списка приложений с GitHub
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** 4.2 блокирует старт тремя сетевыми запросами (A10).

**Решение.** Обновление `AppsList.txt` и `Warning.txt` идёт в фоне после открытия окна (настройка `UpdateListsOnStartup`, по умолчанию включена) и по кнопке. ## ADR-014. Тесты без зависимости от версии Pester

**Контекст.** В Windows встроен Pester 3.4, а синтаксис Pester 5 с ним несовместим.

## ADR-015. Вывод `auth info` / `auth login` не пишется в журнал
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** При реальном запуске в журнал уровня DEBUG попала JSON-строка `auth info` с именем владельца аккаунта. Email маскируется, имя — нет, а SECURITY.md запрещает его логировать.

**Решение.** У `Invoke-DreddIpatool` есть флаг `-QuietOutput`: вывод процесса не передаётся в журнал (в журнал идёт только замаскированная команда и код возврата). Флаг используется для `auth info` и `auth login`. Тест проверяет, что имя из фейкового `auth info` не попадает в сообщения.

**Последствия.** Для разбора проблем со входом нужен режим отладки ipatool и ручной запуск. Журнал 4.3 личные данные аккаунта не содержит.

## ADR-016. В диалоге версий нет даты
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** Проверено на реальном ipatool: `get-version-metadata` возвращает в `releaseDate` одну и ту же дату для всех версий приложения (дату первого выпуска), а не дату конкретной версии.

**Решение.** Колонка даты в диалоге выбора версий не показывается, отображаются номер версии и ID. Поле `ReleaseDate` в ядре сохранено.

**Последствия.** Пользователь не будет введён в заблуждение одинаковыми датами. Если ipatool начнёт отдавать дату версии, колонку можно вернуть одной строкой XAML.

## ADR-017. Цвет текста наследуется от окна, а не задаётся неявным стилем
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** Стили лежат в ресурсах приложения. Неявный стиль `TextBlock` с `Foreground` на этом уровне применяется и к текстам внутри шаблонов кнопок и перебивает их цвет: в светлой теме текст на акцентной кнопке становился тёмным.

**Решение.** Неявный стиль `TextBlock` задаёт только обрезку текста. Цвет текста окна задаётся через `Window.Foreground` и наследуется, а шаблоны кнопок задают `TextBlock.Foreground` сами.

**Последствия.** При добавлении элементов, у которых есть свой цвет по умолчанию (например, `ToggleButton`), цвет нужно задавать явно через ресурс `Brush.Text`.

## ADR-018. Установка IPA с диска без переподписи, с проверкой подписи
**Дата:** 2026-10-17 · **Статус:** принято

**Контекст.** Пользователь хочет ставить любые IPA, как в Sideloadly/iMazing. `ideviceinstaller` передаёт IPA как есть, и iOS принимает только приложения с действующей подписью, подходящей устройству. Sideloadly ставит «любые» IPA потому, что переподписывает их сертификатом пользователя: бесплатный Apple ID даёт подпись на 7 дней и не больше 3 приложений.

**Решение.**
1. Сейчас: установка любого IPA с диска (выбор файла и перетаскивание, без копирования) и добавление в библиотеку (копия). Перед установкой проверяется подпись: тип по `embedded.mobileprovision`, срок, UDID устройства в профиле, флаг `cryptid` в исполняемом файле (0 — расшифрованный IPA с нарушенной подписью). Блокирующие проблемы показываются до запуска, с выбором «Отмена / Всё равно установить / Пропустить проблемные».
2. Переподпись — отдельная задача (BACKLOG #37). Варианты: (а) свой сертификат `.p12` + `.mobileprovision` и подпись через `zsign`; (б) бесплатный Apple ID как в Sideloadly: вход в Apple Developer Services, создание сертификата и профиля, обновление каждые 7 дней. Вариант (б) — большой объём работы, требует согласования.

**Последствия.** Подписанные IPA (App Store, Ad Hoc с UDID устройства, Enterprise) ставятся из IPA Dredd. Расшифрованные и модифицированные IPA честно помечаются «нужна переподпись», а не падают с непонятной ошибкой `ideviceinstaller`.

## ADR-019. IPA Dredd самостоятелен: свой MainApp
**Дата:** 2026-10-17 · **Статус:** принято (уточняет ADR-004)

**Контекст.** Пользователь хочет, чтобы IPA Dredd не зависел от папки 4.2.

**Решение.** `IPA_Downloader_4.2.0/MainApp` (все 4 платформы, 203 МБ) скопирован в `IPA_Dredd_4.3.0/MainApp`. По порядку поиска ADR-004 он теперь основной (источник `app`), а 4.2 остаётся запасным вариантом. `MainApp/` по-прежнему в `.gitignore`: бинарники не храним в git, в релиз их кладёт `tools/Build-Release.ps1`.

**Последствия.** Папку `IPA_Dredd_4.3.0` можно переносить отдельно. Обновлять ipatool нужно в `IPA_Dredd_4.3.0/MainApp`.

## ADR-020. Библиотека покупок: история покупок + iTunes Lookup, статусы только из фактов
**Дата:** 2026-11-03 · **Статус:** принято

**Контекст.** `list-purchases --all` отдаёт только `id, kind, name, price, purchaseDate` (проверено на реальном аккаунте). Возможность скачать знает только сервер Apple в момент загрузки.

**Решение.**
- Источник списка — история покупок (только `iOS/iPad App`, один ID — одна запись с самой ранней датой).
- Метаданные и наличие в магазине — публичный `itunes.apple.com/lookup` пачками по 150 в регионе аккаунта (`auth info` → storefront). Неизвестный регион — Lookup не выполняется («Не проверено»), регион не угадывается.
- «Не удалось скачать» — только по результату реальной попытки (`Set-DreddPurchaseAttempt`), сбрасывается при успехе.
- Кэш `Files/Purchases/<SHA-256(email)[0..16]>.json`, иконки `Files/Cache/Icons/<ID>.jpg`; обе папки в `.gitignore`, в релиз не входят.
- Купленные приложения скачиваются без `--purchase`.

**Последствия.** Статуса «не приобретено» нет. Устанавливалось ли приложение на устройство — по истории узнать нельзя; это не показывается.

## ADR-021. Главная удалена, журнал — в строке состояния
**Дата:** 2026-11-03 · **Статус:** принято (заменяет часть ADR-011 о составе экранов)

**Решение.** Стартовый экран — «Покупки». Статус аккаунта — в боковой панели (по клику — Apple ID), окружение — в «Диагностике», последние операции — история «Загрузок». Журнал свёрнут в строку состояния (последнее сообщение + задачи), разворачивается по клику/Ctrl+L, состояние хранится в `Settings.txt` (`LogExpanded`).

## ADR-022. Релиз без бинарников, компоненты — при первом запуске
**Дата:** 2026-11-04 · **Статус:** принято (заменяет ADR-019 для публичных релизов)

**Контекст.** В ipatool-cpp при сборке вшиваются библиотеки Apple (CoreFP и др.), которые автор ipatool-cpp помечает как не предназначенные для распространения; ideviceinstaller — GPL-2.0. Публичный репозиторий и релизы IPA PILOTDREDD не должны распространять этот код.

**Решение.** Git и portable-архив содержат только код IPA PILOTDREDD. При первом запуске без `MainApp` программа предлагает «Загрузить компоненты»: архив последнего релиза IPA Downloader с GitHub, проверка SHA-256 из GitHub API, пробный запуск ipatool, копирование папки платформы в `MainApp/`. Тот же механизм обновляет ipatool позже. `tools/Build-Release.ps1 -IncludeBinaries` — сборка для себя.

**Последствия.** Первый запуск требует интернета и ~100 МБ загрузки. Публичный архив весит ~0,3 МБ.

## ADR-023. Одна версия программы — файл VERSION
**Дата:** 2026-11-04 · **Статус:** принято

**Решение.** Номер версии IPA PILOTDREDD хранится только в `VERSION` (окно, exe, имя релиза, User-Agent). Номер релиза upstream, из которого взят ipatool, хранится в `MainApp/ipatool-version.txt` (с 4.5.1 версия ipatool-cpp — в `ipatool-cpp-version.txt`, ADR-025) и показывается только в «Диагностике» как техническая деталь; в уведомлениях чужие номера версий не показываются.

## ADR-024. Белый список в .gitignore
**Дата:** 2026-11-04 · **Статус:** принято

**Решение.** `.gitignore` игнорирует всё (`/*`) и разрешает только код, тесты, документацию и `Files/AppsList.txt`. Новые файлы с личными данными по умолчанию не попадут в git.

## ADR-025. ipatool обновляется напрямую из релизов ipatool-cpp
**Дата:** 2026-11-09 · **Статус:** принято (дополняет ADR-022)

**Контекст.** 6 ноября 2026 Apple изменила вход в App Store. Исправленный ipatool-cpp 1.3.0 вышел 9 ноября, а сборка IPA Downloader с ним — нет. Пока обновления шли только через релизы IPA Downloader, исправление не доходило до пользователей.

**Решение.** Первая установка (`NeedsSetup`) по-прежнему берёт набор IPA Downloader (`UpdateRepo`): ipatool и инструменты iPhone. Все дальнейшие обновления ipatool — из релизов ipatool-cpp (`ToolRepo = Sorvigolova/ipatool`), архив `<платформа>_ipatool-cpp.zip` с одним файлом. Его версия записывается в `MainApp/ipatool-cpp-version.txt`; если её нет, обновление предлагается один раз. Сразу после первой установки запускается проверка с установкой свежего ipatool-cpp. Проверки прежние: SHA-256 из GitHub API, пробный запуск, копия в `MainApp_previous`, откат.

**Последствия.** Исправления ipatool доходят без новой версии программы и без ожидания IPA Downloader. Инструменты iPhone обновляются только переустановкой набора.

## ADR-026. Запускатор со встроенным PowerShell, один exe на все версии
**Дата:** 2026-11-09 · **Статус:** принято

**Контекст.** Защитник Windows у пользователя заблокировал `IPA_PILOTDREDD.exe` 4.5.0 («вирус или нежелательная программа»). Запускатор стартовал скрытый `powershell.exe -ExecutionPolicy Bypass -WindowStyle Hidden` — типичный для вредоносных программ приём — и пересобирался к каждой версии (новый хеш, нулевая репутация).

**Решение.** Запускатор выполняет `IPA_Dredd.ps1` в своём процессе через System.Management.Automation (Windows PowerShell 5.1 есть в каждой Windows 10/11); политика выполнения задаётся только для процесса. Версия файла постоянная. Готовый exe хранится в `tools/Launcher/` вместе с хешем исходников `launcher.sha256`; релизы копируют его, пересборка — только при изменении `Launcher.cs` или иконки (CI проверяет соответствие). `Start_IPA_Dredd_Windows.bat` остаётся запасным способом.

**Последствия.** Один и тот же exe переходит из релиза в релиз. Подписи по-прежнему нет; если ложные срабатывания продолжатся — отправка файла в Microsoft и/или подпись (SignPath для open-source).

## ADR-027. Тесты и релизы — в GitHub Actions
**Дата:** 2026-11-09 · **Статус:** принято

**Решение.** `tests.yml`: на каждый push — тесты ядра, самопроверка GUI (в том числе через exe), соответствие exe исходникам. `release.yml`: по тегу `vX.Y.Z` — проверка `VERSION` и заметок, тесты, сборка zip, подпись происхождения (`actions/attest-build-provenance`), публикация релиза с `docs/release-notes/X.Y.Z.md`. Самопроверка GUI использует свою папку сессий и никогда не читает настоящий `~/.ipatool`.

**Последствия.** Архив собран из открытого кода; проверка: `gh attestation verify <zip> -R PiloTDredd/IPA_PILOTDREDD`. Для push изменений в `.github/workflows` токену gh нужно право `workflow`.
